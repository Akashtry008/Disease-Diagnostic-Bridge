DIAGNOSTIC BRIDGE PLATFORM - COMPLETE DEVELOPER'S MANUAL & BUILD GUIDE

This manual outlines the step-by-step process of constructing the "Global Rare-Disease Diagnostic Bridge (RAG)" platform from scratch. Anyone reading this guide will be able to reconstruct the entire application, including tools, installations, algorithms, and style sheets.

========================================================================
PART 1: SYSTEM REQUIREMENTS AND STACK
========================================================================
* Framework: React (v18+) with Vite Build System
* Styling: Custom Vanilla CSS (maximizing flexibility and responsiveness)
* Icon Suite: Lucide React
* Animation Engine: Framer Motion
* Target Environment: Modern Desktop & Mobile Browsers (Chrome, Edge, Safari)

========================================================================
PART 2: INSTALLATION AND PROJECT BOOTSTRAPPING
========================================================================
Run these commands in your shell to initialize and set up the codebase:

1. Create Vite React App:
   ```bash
   npm create vite@latest ./ -- --template react
   ```
2. Install Core Dependencies:
   ```bash
   npm install lucide-react framer-motion
   ```
3. Boot the local Hot-Reload server:
   ```bash
   npm run dev
   ```

========================================================================
PART 3: CORE DATA VAULT AND ALGORITHMS (RAG SPACE)
========================================================================
The platform uses a simulated Vector Database and a Cosine Similarity Ingestion Engine.

Step 3.1: Create the Local Vault Database
File: src/data/researchDatabase.js
* Write a database array containing peer-reviewed scientific publications on rare genetic conditions.
* Each entry must include unique identifiers (`id`), title, authors, year of publication, variant tags, and descriptive snippets.
* Sample tags: "scn1a", "epilepsy", "cacna1a", "ataxia", "mecp2", "gba", "dmd".

Step 3.2: Write the Similarity Matching Algorithm
File: src/data/analysisEngine.js
* Implement a tokenizer helper that extracts clinical terms, converting text input to lower-case arrays.
* Code the vector match calculations:
  * For each publication in `researchDatabase.js`, calculate an overlap score:
    `Overlap Score = (Number of matched tags between user search and publication) / (Total search tokens)`
  * Grade confidence based on overlap percentages:
    * >= 60% Overlap: HIGH Confidence
    * >= 30% Overlap: MODERATE Confidence
    * > 0% Overlap: LOW Confidence
* Return ranked search outputs alongside custom differential analysis statements, pathway diagnostics suggestions, and plain-language patient summaries.

========================================================================
PART 4: COMPONENT CONSTRUCTION
========================================================================
Create these structural components inside the `src/components/` folder:

Step 4.1: Symptom Intake Form
File: src/components/SymptomIntake.jsx
* Renders a textarea allowing clinicians to type phenotypic lists.
* Includes a submit button displaying loading indicators ("Calibrating Neural Bridge...") during search queries.
* Renders a checklist of clinical constraints reminding clinicians to check variant overlays.

Step 4.2: Reasoning Bridge Animation
File: src/components/DiagnosticBridge.jsx
* Animates a list of document indicator nodes simulating search indices.
* Iterates through indices to show "scanning archives" status.
* Displays a detailed card of the matching vector snippet as it scans.
* Includes print and trash shortcuts.
* Employs `flex-wrap: wrap` to prevent layout overflow on mobile screens.

Step 4.3: Diagnostic Report Synthesis
File: src/components/DiagnosticReport.jsx
* Renders a layout displaying:
  * Caregiver Translation: Employs standard formatting to explain findings clearly.
  * Clinical Summary: Displays technical diagnostic abstracts.
  * Peer-Reviewed Matches: Lists active publications with HPO codes.
  * Recommended Pathway: Outlines lab tests (e.g. EEG, Enzyme Assays).
  * Clinical Disclaimer: Clear red warning card stating the tool is educational.

========================================================================
PART 5: INTERACTIVE LAYERS & SYSTEM PORTALS (App.jsx)
========================================================================
Integrate these layout systems in `src/App.jsx`:

Step 5.1: The Clinician Login Gate & Self-Registration
* Intercepts access to the User Module until a valid clinician license is validated.
* Renders a self-registration toggle form allowing new doctors to enter their name, role, and desired license key.
* Auto-fills and registers new keys, updating logs in the Admin Console.
* Floats the verification panel over a high-tech `CanvasMedicalBG` rendering a moving constellated neural network (75 particles, radius 4.5px to 8.5px, glow shadows, and connecting lines).

Step 5.2: The Onboarding Tour Guide
* Uses an interactive step-by-step popup to walk logged-in clinicians through the interface.
* Blurs all elements in the background using `backdrop-filter: blur(6px)`.
* Highlights the current target element by writing style blocks setting `z-index: 10000` on the active component.
* Dynamically shifts the tour guide card: bottom-left when highlighting right-hand sections, and bottom-right otherwise, with a smooth sliding transition.

Step 5.3: The Secure Admin Portal
* Secured via double-click on the Microscope Brand Logo and entering passcode `admin123`.
* Standardized under a High-Security Midnight Slate (`#0b0f19`) and Cobalt Blue (`#3b82f6`) theme.
* Contains tabs for overview statistics, RAG vault ingestion forms, active license registries, and a compliance ledger tracking logins/queries.

========================================================================
PART 6: STYLING AND MEDIA CONTROLS
========================================================================
File: src/index.css
* Define CSS variables for Emerald user theme and Cobalt admin theme.
* Use `overflow-y: auto` on `.content-area` so both the bridge and the report scroll smoothly as a single unit on desktop.
* Define media queries (`@media (max-width: 1024px)`) to stack columns vertically and adapt the sidebar navigation to a horizontal bottom menu bar.
